## 2. B 类：时效性、刊名与参考文献样式

### B1. `iturp526` 引的是已被取代的版本（**建议处理**）

- 条目：`refs.bib:11-18`，`P.526-15`，`year = {2019}`。
- 已核实：`P.526-15` 的批准日期是 **2019-10**（ITU 官方记录 `REC-P.526-15-201910`），所以 `year = 2019` 本身**没错**。
- **但 ITU-R P.526 的现行版本已是 `P.526-16 (11/2025)`**（ITU 官方 PDF：`https://www.itu.int/dms_pubrec/itu-r/rec/p/R-REC-P.526-16-202511-I!!PDF-E.pdf`）。对本稿而言，`P.526-15` 确实就是撰写时的现行版，**可以在正文里写一句"the version in force at the time of writing"**，或直接把版本号/URL 写进条目以便审稿人一步定位。
- 另外，该条目**缺 `number = {P.526-15}` 与 URL**（版本号只藏在 `title` 里），IEEE 稿件通常希望 ITU-R 建议书带可解析链接。
- 说明：本稿用到的 `J(ν)=6.9+20lg(…)`（`main.tex:1037`）是单刃峰经验式，跨版本未变，**换版本号不影响任何计算**。

### B2. 参考文献样式不是 IEEE T-ITS 要求的样式（**格式类，内容无误**）

- `main.tex:1717` 用的是 `\bibliographystyle{unsrt}`，文档类为 `article`（`main.tex:10`）。
- 事实：IEEE T-ITS 投稿要求 `IEEEtran` 类 + `IEEEtran.bst`；`unsrt` 会输出**全称刊名**（"IEEE Transactions on Wireless Communications"），而 IEEE 格式要求缩写（"IEEE Trans. Wireless Commun."）。
- **刊名本身全部是现行名称、且条目之间风格自洽**（详见 §5 已核查清单），所以这不是"刊物改名"问题，而是"样式表选错"问题。若最终按 `IEEEtran.bst` 重排，刊名会自动缩写，无需改 `refs.bib`。

## 9. 复核脚本（可复现本报告的全部结论）

本报告的 DOI/作者核验逻辑，**已作为 `--audit-bib` 模式并入 `code/_verify_refs.py`**（纯新增，不改动原有默认行为）：

```powershell
cd R:\claude\bitget_grid\国赛路嗯嗯\D题
H:\python\python.exe code\_verify_refs.py --audit-bib `
    --out results\文献审计_反查.json
```

该模式做的事：

1. 解析 `refs.bib` 全部 `@type{key, ...}` 与字段（`_parse_bib`）；
2. 对每个 `doi` 字段 `GET https://api.crossref.org/works/<doi>`（`lookup_doi`），404 直接报错；
3. 比对**题名**（去 LaTeX 转义后前缀包含）与 **`year`**（同时接受 `issued` / `published-print` / `published-online` 三者之一，避免把"在线 2020、印刷 2021"误报为错）；
4. 把**作者姓氏集合**与 Crossref 作者集合求差（`_surname` 用 `unicodedata` 归一重音，所以 `Kr{\'o}l`→`krol` 不会误报；条目带 `and others` 时只查"多列"不查"漏列"）；
5. Crossref 未登记作者时（部分 `@book` 只登记编者）跳过作者比对，不制造噪声。

**本报告的实际运行输出（可复现）：**

```

[CHK ] deygout          TITLE-MISMATCH; AUTHOR-NOT-IN-CROSSREF(deygout); MISSING-AUTHORS(kaneyee)
[CHK ] zengtraj         AUTHOR-NOT-IN-CROSSREF(xu)
[CHK ] relay5g          TITLE-MISMATCH; AUTHOR-NOT-IN-CROSSREF(zeng,lyu,zhang); MISSING-AUTHORS(namuduri)
[CHK ] gomez2016        AUTHOR-NOT-IN-CROSSREF(buratti,reede,fitch)
...
反查结果：29 一致 / 4 有问题 / 2 无 DOI 可查（共 35 条）
```

其余 29 条全部 `[OK]`，与 §5.1 的清单逐条对应。明细落在 `results/文献审计_反查.json`。

> **为什么必须补这一步**：`code/_verify_refs.py` 原有的 `CANDIDATES`/`EXTRA` 逻辑只做"**按标题正向查询**"（`query()` → `norm()` 包含匹配），**从不反查 `refs.bib` 里已经存在的条目**。这正是 `deygout`、`relay5g`、`zengtraj`、`gomez2016` 四处能长期存活的原因——它们四条从未进入 `CANDIDATES`/`EXTRA` 列表，因此那句"the bibliography is machine-verified against Crossref"在事实层面从未覆盖它们。
