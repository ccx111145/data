# English SCI manuscript — reproduction guide

**Title.** Joint Transport–Relay Co-Design for UAV Emergency Logistics in
Mountainous Terrain: Handover-Aware Feasibility, Channel-Model Sensitivity, and
the Price of Partitioning

This directory holds the English journal manuscript and everything needed to
regenerate it from scratch. The companion competition paper (Chinese) lives in
`../paper/` and is unaffected by anything in this folder.

```
paper_en/
├─ main.tex                   manuscript source (class-agnostic, single column)
├─ main.pdf                   compiled (22 pages; xelatex + bibtex)
├─ main_elsarticle.tex/.pdf   DERIVED: Elsevier elsarticle (37 pages, preprint)
├─ main_ieee.tex/.pdf         DERIVED: IEEEtran two-column (12 pages)
├─ refs.bib                   bibliography (verified, public references only)
├─ numbers_en.tex             ALL numbers as macros (generated)
├─ numbers_en_sources.txt     provenance of every macro
├─ build/                     scratch dir for the journal variants (figs/ + aux)
└─ figs/                      figures used by the manuscript
```

The two journal variants are **derived** files: `code/make_elsarticle.py` replaces
only the preamble and the front matter and leaves the body byte-identical, so
the three PDFs can never disagree about a number, a theorem or a figure.

From the code directory:

```powershell
cd code
$env:PYTHONHASHSEED = "0"          # mandatory: ALNS sampling depends on the hash seed

python run_all_en.py --only pdf    # recompile the manuscript only

python run_all_en.py               # whole pipeline, full budgets (~35 min)
```

## 2. What every macro means

The manuscript contains **no hard-coded numbers**. Each is a macro defined in
`numbers_en.tex` and generated by `code/make_numbers_en.py` from the result
files. `numbers_en_sources.txt` lists, for every macro, the file it came from.

If a result file is missing, the corresponding macro renders as a red **TBD**
rather than silently reusing a stale value. A manuscript with any `TBD` must
not be submitted.

Control sequences in LaTeX cannot contain digits, hence names such as
`\ENchAltNStar` (P.526 model) and `\ENqTwoSorties` instead of `\ENq3N2Sorties`.

## 3. Core claims and where their evidence lives

| Claim | Evidence |
|---|---|
| A coverage-only (instant-relocation) relay model is **not executable**: it understates the fleet by 2 vehicles; the true optimum is bracketed as $2 \le N^* \le 3$ | `results/中继基线与下界.md` |
| Replacing the constant occlusion penalty with ITU-R P.526 knife-edge diffraction raises outage demand by 32.2 %, cuts usable hover points by 49.2 %, and raises $N^*$ from 3 to 4 (stable across candidate budgets 200/400/600) | `results/信道模型对比.md` |
| Air transit (M2) cuts the median blackout from 1116 s to 471 s and lifts the $(\star)$ rate from 72.0 % to 93.1 %, yet $N=2$ remains infeasible in **both** modes | `results/换位模式对比.json`, `results/跨度黑障不等式.json` |
| Optimising departure instants alone does **not** remove the obstruction: the deficiency is unchanged and no shift is accepted | `results/协同再调度.md` |
| Fleet size is **not** monotone in the occlusion ratio (ρ = −0.23) but correlates with temporal fragmentation (ρ = +0.47) | `results/多地形基准.md` |
| $N=2$ is infeasible in the strong sense: the unpruned recursion returns an empty state set over the declared candidate set, and the energy bound gives $N \ge 2$ independently of any search | `results/局部阻塞证书.json`, `results/DP阻塞诊断_N2_*.json` |
| The obstruction lives at **instant** granularity, not phase granularity: a phase-level integer program is satisfiable at $N=2$ (CP-SAT closes it in 0.7 s), while the cell-level recursion is not; the missing ingredient is the intra-phase alibi requirement | `results/中继ILP松弛.json` (`code/relay_ilp.py`) |

## 4. Method notes that matter for reproduction

* **Two layers of restriction, both declared.** An infeasibility claim depends on
  (i) the **candidate set** $C_0$ — the hover points that can individually cover at
  least one demand cell (2436 of 2471 here) — and (ii) a **per-cell candidate
  refinement** (top-12 nearest points that can complete the demand of that cell).
  The state-pruning parameters are a third, weaker layer: the candidate-budget
  sweep in `results/DP阻塞诊断_N2_*.json` shows the failure position moving from
  cell 171 (topk 12) to cell 225 (topk 24 and 40) and then staying there, always
  with zero admissible transitions at the failing cell. Proposition
  "distinguishing candidate set" in the manuscript covers layers (i) and (iii),
  **not** (ii), which is why the refinement is always reported alongside.
* **Time-window convention.** The span inequality uses a window in *seconds*:
  for demand cell $k$, let $j_k$ be the first cell with $t_j \ge t_k - w$. The
  requirement is $\mathrm{span}[j_k] \ge k - j_k + 1$, where `span` is the
  longest run over which **one single** hover point covers everything. Cells are
  not uniformly spaced, so an index-based window ($k - w/\Delta$) is wrong; and
  taking the union over points before looking for a run silently allows free
  per-cell re-selection, which makes the inequality vacuous. See
  `code/span_util.py`.
* **Node elevations under terrain transformations.** The elevations supplied with
  the benchmark belong to the original terrain. When the elevation field is
  scaled, translated or walled, they must be re-derived from the transformed
  DEM, otherwise the aircraft is routed below ground and the resulting outages
  are spurious. The identity transform is deliberately left untouched so that
  the reference instance stays bit-identical to the competition paper.
* **The manuscript compiles from three different layouts.** `\InputRes` tries the
  bare filename first, then `paper_en/`, then `../paper_en/`, then `../`; the
  manuscript is therefore compilable from the workspace root
  (`xelatex paper_en/main.tex`), from inside `paper_en/`, and from the delivery
  package (where the sources sit in `06_英文SCI稿/`). The journal variants are
  built in a scratch `paper_en/build/` directory that receives `figs/`,
  `numbers_en.tex` and `refs.bib`, because xelatex resolves graphics relative to
  the working directory rather than to the source file.
* **Feasibility is certified constructively.** A feasible $N$ is proven by
  exhibiting a complete schedule (two heuristic variants are tried; either one
  succeeding suffices). Failure to find a schedule for $N \le 4$ is reported as
  such and never as a proof of infeasibility.
* **Sampling.** Outage statistics are evaluated on a fixed 10 s grid. The paper
  claims "sampling-verified", not "verified in continuous time".

## 6. Preparing a submission to a specific journal

`main.tex` is written in a **single-column `article` layout with standard
packages only** (`amsmath`, `amsthm`, `booktabs`, `graphicx`, `hyperref`,
`siunitx`, `enumitem`, `algorithm`/`algpseudocode`). It compiles as-is and is
deliberately class-agnostic. Two publisher variants are **already generated and
verified to compile**:

| File | Class | Length | Target venues |
|---|---|---|---|
| `main_elsarticle.pdf` | `elsarticle` (preprint, single column) | 37 pages | *Computers & Operations Research*, *Reliability Engineering & System Safety* |
| `main_ieee.pdf` | `IEEEtran` (journal, two column, 10 pt) | **12 pages** | *IEEE T-ITS*, *IEEE TVT* |

The IEEE build at 12 pages sits inside the usual Transactions page budget, so the
material as it stands would not need to be cut for a regular paper; the Elsevier
build is in preprint mode and would be typeset to roughly half that length in
final form.

Two content decisions should be revisited per venue: (i) *T-ITS* and *TVT*
expect the communication layer to be the organising principle, so
Sections 5.2--5.4 (channel, handover premium, relocation mode) should be
promoted and the partitioning material moved to an appendix; (ii) *C&OR* and
*RESS* expect the decision model to lead, so the partitioning and risk framings
should be expanded and the propagation detail compressed.

Nothing in the numbers depends on the layout: every value is a macro from
`numbers_en.tex`, so re-flowing the text cannot desynchronise the figures,
tables and claims.


## 10. Two-column layout fixes (IEEE variant)

The body is shared by three layouts, but the display width is not: a table that
fits a single-column page overflows an IEEEtran column. Three macros in the body
make the same source safe in both:

* `\fitwide{...}` around every `tabular` --- shrinks a table to `\linewidth` only
  when its natural width exceeds it (uses `graphicx`'s `\width`), so tables stay
  at natural size in the single-column builds.
* `\eqfit{...}` around the three widest display equations --- same rule, so no
  equation is pushed past the column edge.
* `\textfloatsep` / `\floatsep` / `\intextsep` are set to 12 pt plus glue, so a
  float can no longer sit flush against the following paragraph.

After these, the IEEEtran build reports **0 overfull boxes** (it previously had
9, several of them tables cut off at the column edge). The `elsarticle` build is
left with one 2.6 pt and two 0.6 pt overfull lines, all in prose.

All figures used by the English manuscript are English-labelled:
`fig_en_env`, `fig_en_channel`, `fig_en_baseline`, `fig_en_theory`,
`fig_en_modes`, `fig_en_feedback`, `fig_en_terrain`. The Chinese figures
(`fig_terrain_phase.png`, `fig_env.png`, ...) stay in `figs/` for the
competition paper and are no longer referenced here.
## 11. Bibliography integrity

The reference list was expanded from 15 to **35 entries** (including two recent IEEE T-ITS papers on truck--drone routing, added to signal venue fit) for the Introduction and
Related Work. Every new entry was verified against Crossref by
`code/_verify_refs.py` before being pasted into `refs.bib`; the raw API responses
are stored in `results/文献核实.json`, and the script prints a
`TITLE_MISMATCH` flag whenever the returned title differs from the query so that a
DOI can never be attached to the wrong paper by accident.

Re-run the check with:

```powershell
python code/_verify_refs.py --extra --out results/文献核实.json
```

Two real defects were caught this way and fixed:

* `10.1016/j.cor.2022.106015` resolves to a *pickup-and-delivery* paper, not to the
  survey it had been cited as --- the entry now carries the author list that
  Crossref returns for that DOI.
* `10.1109/LCOMM.2016.2578312` ("Efficient deployment of multiple UAVs") is by
  **Mozaffari et al.**, not by Al-Hourani et al., whose paper is the different
  `10.1109/LWC.2014.2342736`; both entries are now correct and cited separately.
* The `mozaffari` tutorial DOI in the original 15-entry list was wrong
  (`...2892147`); it is `10.1109/COMST.2019.2902862`.

All 35 entries are cited in the text and all `\cite` keys resolve: the build
reports 0 undefined citations.
## 12. Figure resolution and vector output

Reviewer-facing requirement: at 100 % zoom in a two-column layout the subplot
titles and legends of Figs. 2, 3, 5, 6 and 7 were small and slightly pixelated.
Two changes fix this at the source rather than in the PDF:

* **Fonts sized for the final column width.** `make_figs_en.py` and
  `make_fig_theory.py` now set `font.size = 11`, `axes.titlesize = 12.5`,
  `axes.labelsize = 11.5`, `legend.fontsize = 10.5`; every in-figure annotation
  below 10.5 pt was raised to 10.5. The DEM study-area figure keeps smaller map
  labels (10 pt) and contour labels (6.5 pt) because that figure is a large map
  scaled *down* into the column, where oversized labels would collide.
* **Vector output.** Every data figure is written twice: a vector PDF for LaTeX
  and a 300 dpi PNG for preview. The new `\Dfig`/`\Dfigfile` macros take the
  figure *name without an extension* and resolve `pdf → png → eps`, so the
  choice is made by which file exists. Only the DEM hillshade stays raster-only:
  it is a photograph-like raster field, and vectorising it would inflate the PDF
  without adding sharpness.

Evidence: the built PDFs contain exactly **one** embedded raster image (the DEM
hillshade, 2636×1750 px); all other figures are vector, and their text is
extractable from the PDF, which is the direct proof that it is vector.

## 13. IEEE variant typography

`IEEEtran` borrows Times glyphs through `TU/ptm/*`, which do not exist under
xelatex; the build therefore fell back to Computer Modern and emitted 148
`Font shape ... undefined` warnings. The IEEE variant is now compiled with
**pdflatex** plus `mathptmx` (`newtxmath` was rejected because it collides with
`amssymb` over `\Bbbk` and `\openbox`). Result: 0 font warnings, text and maths
uniformly Times, still 12 pages and 0 overfull boxes. `code/make_elsarticle.py`
selects the engine per variant, so the other two keep using xelatex.

## 14. Table VII wording

The table entry `ALNS (no CP-SAT)` was ambiguous next to the row `ALNS + CP-SAT`;
it now reads `ALNS w/o CP-SAT (ablation)`, which also avoids any hyphenation risk
